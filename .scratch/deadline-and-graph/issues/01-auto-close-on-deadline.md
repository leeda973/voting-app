# 01: 자동 마감: 마감 시각이 지난 투표를 마감으로 판단

**만들 것:** 투표에 마감 시각을 저장할 수 있게 되고, 마감 시각이 지난 투표는 어디서 보든 마감이다. 표를 남길 수 없고, 표를 남기지 않은 사람도 결과를 보고, 목록의 마감 섹션에 있고, 관리자의 마감하기는 이미 마감된 투표로 처리된다. 마감 시각을 정하는 화면은 02에서 만들므로 이 티켓은 DB에 마감 시각을 직접 넣어 확인한다. 마감 시각이 없는 기존 투표는 지금과 똑같이 동작한다.

먼저 사전 리팩터링으로, 투표의 진행 중/마감을 읽는 모든 곳(목록, 상세, 결과, 표 저장, 마감)이 **실제 상태** 판단 하나를 쓰게 모은다. 투표 규칙 모듈의 시각에 따라 답이 바뀌는 함수는 현재 시각을 인자로 받게 바꾼다.

TDD로 투표 규칙 모듈의 **실제 상태**와 **실제 마감된 시각** 규칙을 먼저 만든다.

스펙: [spec.md](../spec.md)의 "마감 판단", "스키마 변경", "마감 시각이 없는 투표", "데이터 규칙 변경"의 표 저장·마감, "API 계약 변경". 결정 배경은 [ADR 0002](../../../docs/adr/0002-deadline-closes-on-read.md).

**차단 요인:** 없음(즉시 시작 가능)

**Status:** ready-for-agent

- [x] 실제 상태 규칙이 테스트로 먼저 작성되어 있다: 마감 시각 없음, 마감 시각 1밀리초 전 / 정각(마감) / 1밀리초 후, 관리자가 마감했지만 마감 시각은 미래
- [x] 실제 마감된 시각 규칙이 테스트로 먼저 작성되어 있다: 관리자가 마감한 시각 우선, 마감 시각이 지나면 그 값, 진행 중이면 없음, 마감 시각 없이 관리자가 마감한 경우
- [x] 목록 분류, 투표 가능 여부, 결과 공개 여부가 실제 상태를 쓰고, 마감 시각이 없는 경우의 테스트가 있다. 시그니처가 바뀐 기존 테스트는 현재 시각을 넘기도록 고쳐져 있다
- [x] `polls`에 `closes_at`(timestamptz, NULL 허용) 열이 스키마 SQL 파일에 있고, `ADD COLUMN IF NOT EXISTS`로 Neon DB에 적용되어 있다. 기존 데이터는 고치지 않는다
- [x] README의 스키마 적용 안내에 이 변경이 적혀 있다
- [x] 코드 안에서 DB 열 `closes_at`은 필드 `deadline`으로, `closed_at`과 헷갈리지 않게 매핑된다
- [x] 표 저장 쿼리와 마감 쿼리의 조건에 "`closes_at`이 NULL이거나 DB 현재 시각보다 뒤"가 들어가 있다. 투표 행 공유 잠금은 그대로다
- [x] 목록, 상세(`PollDetail`), 결과(`Result`)의 `status`와 `closedAt`, `canViewResult`가 실제 상태 기준이다. `PollSummary`와 `PollDetail`에 `deadline`(UTC ISO 또는 `null`)이 있고, `PollSummary`에 `closedAt`이 있다
- [x] DB에 마감 시각을 과거로 넣은 투표에 대해: 표 남기기는 409 `poll_closed`, 표 없는 투표자도 결과 200, 목록의 마감 섹션에 있음, 관리자 마감은 409 `already_closed`, 상세 화면에 마감 버튼이 없음
- [x] 마감 시각이 없는 기존 투표로 표 남기기, 결과, 마감, 삭제가 지금과 같다
- [x] `npm test`, `npm run lint`, `npm run build`가 통과한다
