# 02: 마감 시각을 정해서 투표 만들기

**만들 것:** 관리자가 투표를 만들 때 "마감 시각 정하기"를 켜면 날짜·시간 입력(휴대폰 기본 선택기)과 "1일 뒤 / 3일 뒤 / 7일 뒤" 버튼이 나타난다. 마감 시각은 한국 시간, 분 단위이고 지금부터 10분 뒤 이후, 30일 뒤 이전만 된다. 벗어나면 입력 옆에 안내가 나온다. "마감 시각은 나중에 바꿀 수 없어요" 안내가 스위치 근처에 항상 보인다. 켜지 않으면 지금처럼 마감 시각 없는 투표가 만들어진다. 만든 투표의 상세 화면에는 "9월 27일(토) 18:00 마감"처럼 한국 시간 마감 시각이 보인다.

TDD로 투표 규칙 모듈의 **마감 시각 검증**(투표 입력 검증 확장)과 **한국 시간 표시** 규칙을 먼저 만든다.

스펙: [spec.md](../spec.md)의 "투표 규칙 모듈 확장"의 입력 검증·한국 시간 표시, "API 계약 변경"의 `POST /api/polls`, "화면"의 투표 만들기.

**차단 요인:** 01 (자동 마감: 마감 시각이 지난 투표를 마감으로 판단)

**Status:** ready-for-agent

- [x] 마감 시각 검증이 테스트로 먼저 작성되어 있다: 없음은 통과, 형식 오류, 9분 59초 뒤 거부 / 10분 뒤 통과, 30일 뒤 통과 / 30일 1분 뒤 거부, "2026-09-27T18:00"은 UTC "2026-09-27T09:00:00.000Z"
- [x] 한국 시간 표시가 테스트로 먼저 작성되어 있다: 요일, 자정을 넘기는 UTC 시각(UTC 15:30 → 다음 날 00:30)
- [x] `POST /api/polls`가 `deadline`(`"YYYY-MM-DDTHH:mm"` 한국 시간 또는 `null`/생략)을 받아 `closes_at`에 저장하고, 검증 실패 시 400 `invalid_input`의 `fields.deadline`에 사유를 담는다
- [x] 투표 만들기 화면에 "마감 시각 정하기" 스위치, 날짜·시간 입력(최솟값·최댓값 설정), 1일/3일/7일 뒤 버튼, "나중에 바꿀 수 없어요" 안내가 있고, 서버의 `deadline` 오류가 입력 옆에 보인다
- [x] 스위치를 끄고 만들면 마감 시각 없는 투표가 만들어진다
- [x] 상세 화면에 한국 시간 마감 시각이 보인다(마감 시각이 없으면 아무것도 보이지 않는다)
- [x] 마감 시각을 바꾸는 API나 화면이 없다
- [x] `npm test`, `npm run lint`, `npm run build`가 통과한다
