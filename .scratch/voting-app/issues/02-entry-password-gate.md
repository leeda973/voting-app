# 02: 입장 비밀번호 게이트

**만들 것:** 입장하지 않은 방문자가 앱의 어떤 주소로 들어와도 입장 화면으로 안내된다. 입장 비밀번호를 맞히면 원래 가려던 화면으로 돌아가고, 이후 30일 동안 다시 묻지 않는다. 틀리면 틀렸다는 안내가 나온다. 입장하지 않은 상태에서 API를 직접 부르면 401이 돌아온다. 입장할 때 이 브라우저를 구분하는 식별 쿠키(1년)가 없으면 함께 발급되며, 이 쿠키는 입장 세션이 끝나거나 비밀번호가 바뀌어도 유지된다.

스펙: [spec.md](../spec.md)의 "쿠키와 세션", "접근 제어", `POST /api/entry`. 결정 배경은 [ADR 0001](../../../docs/adr/0001-shared-passwords-and-cookie-voting.md).

**차단 요인:** 01 (기반: 스키마 적용과 빈 투표 목록)

**Status:** ready-for-agent

- [x] 입장하지 않은 상태로 `/`나 `/polls/<아무 id>`를 열면 입장 화면으로 이동하고, 원래 주소가 보존된다
- [x] 올바른 입장 비밀번호를 입력하면 원래 주소로 돌아간다(원래 주소가 없으면 `/`)
- [x] 틀린 비밀번호는 401 `wrong_password`와 한국어 안내로 거부된다
- [x] 입장하지 않은 상태에서 `GET /api/polls`를 부르면 401이 돌아온다
- [x] 입장 세션 쿠키는 서명되어 있고 30일 뒤 만료되며, `HttpOnly`, `SameSite=Lax`, 운영 환경 `Secure`다
- [x] 브라우저 식별 쿠키가 없으면 입장할 때 무작위 값으로 1년짜리가 발급되고, 이미 있으면 그대로 유지된다
- [x] `ENTRY_PASSWORD`를 바꾸면 기존 입장 세션이 무효가 되지만 브라우저 식별 쿠키는 그대로다
- [x] 비밀번호 비교가 타이밍 공격에 안전한 방식이다
- [x] 입장 확인은 Next.js 16의 `proxy`에서 한다(`node_modules/next/dist/docs/`의 proxy 문서 확인)
- [x] 세션 서명과 검증처럼 DB가 필요 없는 로직은 테스트가 있다
- [x] `npm test`, `npm run lint`, `npm run build`가 통과한다
