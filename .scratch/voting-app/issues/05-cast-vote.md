# 05: 표 남기기

**만들 것:** 투표자가 진행 중인 투표의 상세 화면에서 선택지 하나를 골라 표를 남긴다. 표를 남긴 뒤 다시 들어오면 투표 폼 대신 이미 투표했다는 상태가 보이고(결과 화면은 06에서 붙인다), 목록에는 "투표 완료"가 표시된다. 같은 브라우저로는 같은 투표에 다시 표를 남길 수 없으며, 입장 세션 쿠키만 지우고 다시 입장해도 마찬가지다. 시크릿 창처럼 다른 브라우저에서는 표를 하나 더 남길 수 있다(의도된 동작). 관리자도 일반 투표자처럼 표를 남길 수 있다.

TDD로 투표 규칙 모듈의 **투표 가능 여부** 규칙을 먼저 만든다.

스펙: [spec.md](../spec.md)의 "투표 규칙 모듈", "데이터 규칙", `POST /api/polls/[id]/votes`, `PollSummary.hasVoted`, `PollDetail.myOptionId`.

**차단 요인:** 04 (투표 만들기와 투표 상세 보기)

**Status:** ready-for-agent

- [x] 투표 가능 여부 규칙이 테스트로 먼저 작성되어 있다: 진행 중이고 처음 투표함(허용), 이미 투표함(`already_voted`), 마감됨(`poll_closed`), 다른 투표의 선택지(`invalid_option`)
- [x] `POST /api/polls/[id]/votes`가 브라우저 식별 쿠키의 값으로 표를 저장하고, 거부 사유에 맞는 오류 코드(400 `invalid_option`, 404, 409 `already_voted`, 409 `poll_closed`)를 돌려준다
- [x] 같은 브라우저에서 동시에 두 번 요청해도 DB 유니크 제약 덕분에 한 표만 저장되고, 두 번째 요청은 409 `already_voted`를 받는다
- [x] 표 저장 쿼리가 "투표가 진행 중일 때만" 조건을 같은 쿼리 안에서 확인한다
- [x] 성공 응답은 스펙의 `Result` 형태다(집계 규칙은 06에서 다듬으므로 지금은 표 수만 맞으면 된다)
- [x] 상세 화면에서 선택지 하나만 고를 수 있고, 표를 남긴 뒤에는 투표 폼이 사라지고 내가 고른 선택지가 표시된다
- [x] `GET /api/polls`의 `hasVoted`와 `GET /api/polls/[id]`의 `myOptionId`가 이 브라우저 기준으로 채워지고, 목록에 "투표 완료"가 보인다
- [x] 입장 세션 쿠키만 지우고 다시 입장해도 같은 투표에 다시 표를 남길 수 없다
- [x] `npm test`, `npm run lint`, `npm run build`가 통과한다
