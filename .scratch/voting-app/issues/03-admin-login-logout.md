# 03: 관리자 로그인과 로그아웃

**만들 것:** 운영진이 `/admin`에서 관리자 비밀번호를 입력하면 그 브라우저가 관리자가 된다. 관리자는 입장 비밀번호를 따로 입력하지 않아도 앱을 쓸 수 있다. 관리자 세션은 1일 뒤 끝나고, 로그아웃 버튼으로 바로 끝낼 수도 있다. 일반 화면에는 `/admin`으로 가는 링크가 없다. 이 티켓이 끝나면 관리자 화면에는 로그아웃 버튼과, 다음 티켓에서 연결할 "투표 만들기" 자리가 보인다.

스펙: [spec.md](../spec.md)의 "쿠키와 세션", "접근 제어", `POST/DELETE /api/admin/session`.

**차단 요인:** 02 (입장 비밀번호 게이트)

**Status:** ready-for-agent

- [x] `/admin`은 입장하지 않은 상태에서도 열리고, 관리자 비밀번호 입력 폼을 보여준다
- [x] 올바른 관리자 비밀번호를 입력하면 관리자 세션 쿠키(1일)가 발급되고, 브라우저 식별 쿠키가 없으면 함께 발급된다
- [x] 관리자 세션만 있고 입장 세션이 없는 브라우저도 `/`와 API를 쓸 수 있다
- [x] 틀린 비밀번호는 401 `wrong_password`와 한국어 안내로 거부된다
- [x] 이미 관리자인 브라우저로 `/admin`에 가면 로그아웃 버튼이 보이고, 누르면 관리자 세션이 끝난다
- [x] 관리자 전용 API가 관리자 세션을 확인하는 공통 방법이 있어 이후 티켓에서 그대로 쓸 수 있다(관리자가 아니면 403)
- [x] `ADMIN_PASSWORD`를 바꾸면 기존 관리자 세션이 무효가 된다
- [x] 일반 화면 어디에도 `/admin` 링크가 없다
- [x] `npm test`, `npm run lint`, `npm run build`가 통과한다

## Comments

- 2026-09-25: 구현 완료. 로컬 `.env.local`에 개발용 `ADMIN_PASSWORD`를 추가했다. 403 가드(`forbiddenUnlessAdmin`)는 단위 테스트로 확인했고, 실제 호출은 티켓 04가 처음이다. 로그아웃 버튼 클릭은 실제 브라우저로 확인하지 않았다(curl로 DELETE 확인).
- 2026-09-25: 요청에 따라 투표 목록 화면 아래에 `/admin` 링크를 추가했다. 위 "일반 화면에 링크 없음" 기준은 더 이상 적용되지 않는다.
- 2026-09-25: 관리자 비밀번호로만 들어온 운영진이 목록에서 로그아웃하면 입장 화면으로 가는데, 그 화면에 관리자 입구가 없어 다시 로그인할 수 없었다. 입장 화면에 "관리자 로그인" 링크를 추가했다.
