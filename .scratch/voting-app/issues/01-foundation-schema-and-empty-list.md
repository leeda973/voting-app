# 01: 기반: 스키마 적용과 빈 투표 목록

**만들 것:** 앱을 열면 Next.js 템플릿 페이지 대신 투표 목록 화면이 나오고, 투표가 하나도 없으므로 "아직 투표가 없어요" 안내가 보인다. 이 화면은 실제로 Neon DB에서 목록을 읽어 온 결과다. 이후 티켓이 TDD로 작업할 수 있도록 테스트 도구와 투표 규칙 모듈의 빈 뼈대도 이 티켓에서 준비한다.

먼저 템플릿 페이지의 예제 코드와 스타일을 걷어내 이후 작업이 깨끗한 상태에서 시작하게 한다(사전 리팩터링).

스펙: [spec.md](../spec.md)의 "데이터베이스 스키마", "API 계약"의 `GET /api/polls`, "테스트 결정 사항".

**차단 요인:** 없음(즉시 시작 가능)

**Status:** ready-for-agent

- [x] 스펙의 투표(`polls`), 선택지(`options`), 표(`votes`) 테이블과 모든 제약(유니크, 복합 FK, 연쇄 삭제, 상태 값 제한)을 담은 스키마 SQL 파일이 있고, `.env.local`의 Neon DB에 적용되어 있다
- [x] 스키마 적용 방법이 README에 한글로 적혀 있다
- [x] `GET /api/polls`가 `{ open: [], closed: [] }` 형태로 진행 중 투표와 마감 투표를 각각 최신순으로 돌려준다(지금은 둘 다 빈 배열)
- [x] `/` 화면이 목록 API의 결과를 진행 중 섹션과 마감 섹션으로 나눠 보여주고, 비어 있으면 안내 문구를 보여준다
- [x] 템플릿 예제 콘텐츠가 제거되어 있고, UI 언어가 한국어이며, 휴대폰 폭에서 가로 스크롤이 생기지 않는다
- [x] Vitest가 개발 의존성으로 설치되어 있고 `npm test`로 실행된다
- [x] DB와 HTTP를 모르는 투표 규칙 모듈의 빈 뼈대와, 그 모듈을 불러오는 테스트 파일 하나가 있으며 `npm test`가 통과한다
- [x] `npm run lint`와 `npm run build`가 통과한다
