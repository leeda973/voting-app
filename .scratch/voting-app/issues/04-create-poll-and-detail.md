# 04: 투표 만들기와 투표 상세 보기

**만들 것:** 관리자가 질문 하나와 선택지 2~10개를 입력해 투표를 만든다. 선택지 입력 칸은 추가하거나 지울 수 있다. 규칙에 맞지 않는 입력은 어느 칸이 왜 틀렸는지 안내와 함께 거부된다. 만들면 바로 그 투표의 상세 화면으로 이동해 질문과 선택지를 보여주고, 관리자는 이 주소를 복사해 단톡방에 공유할 수 있다. 목록의 진행 중 섹션에는 새 투표가 최신순으로 나타난다. 만든 투표는 수정할 수 없다.

TDD로 투표 규칙 모듈의 **투표 입력 검증** 규칙을 먼저 만든다.

스펙: [spec.md](../spec.md)의 "투표 규칙 모듈", "데이터 규칙", `POST /api/polls`, `GET /api/polls/[id]`, "테스트 결정 사항"의 입력 검증 경우.

**차단 요인:** 03 (관리자 로그인과 로그아웃)

**Status:** ready-for-agent

- [x] 투표 입력 검증 규칙이 테스트로 먼저 작성되어 있다: 질문 빈 칸·공백만·100자·101자, 선택지 1·2·10·11개, 선택지 50자·51자, 공백 차이만 있는 중복(`"치킨"`과 `" 치킨 "`), 앞뒤 공백 제거 결과
- [x] `POST /api/polls`는 관리자만 쓸 수 있고(아니면 403), 잘못된 입력에는 400 `invalid_input`과 필드별 사유를 돌려준다
- [x] 투표 1건과 선택지들이 한 트랜잭션으로 저장되고, 선택지는 입력 순서대로 `position`이 매겨진다
- [x] `/polls/new` 폼에서 선택지 칸을 추가하거나 지울 수 있고(2~10개 범위 안에서), 서버가 돌려준 필드별 오류를 해당 칸 옆에 한국어로 보여준다
- [x] 투표를 만들면 `/polls/<id>`로 이동한다
- [x] `GET /api/polls/[id]`가 스펙의 `PollDetail` 형태로 질문, 상태, 선택지(표시 순서대로)를 돌려주고, 없는 id면 404 `not_found`다
- [x] 투표 상세 화면이 질문과 선택지를 보여주고, 없는 투표면 없는 투표라고 안내한다
- [x] 목록의 진행 중 섹션에 투표가 최신순으로 보이고, 누르면 상세 화면으로 간다
- [x] 관리자 화면(`/admin`)에서 투표 만들기로 갈 수 있다
- [x] `npm test`, `npm run lint`, `npm run build`가 통과한다
