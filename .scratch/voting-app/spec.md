# 스펙: 동아리 투표 앱

Status: ready-for-agent

용어는 [CONTEXT.md](../../CONTEXT.md)를 따른다. 접근 제어와 중복 투표 방지 방식은 [ADR 0001](../../docs/adr/0001-shared-passwords-and-cookie-voting.md)을 따른다.

## 문제 정의

동아리에서 회식 메뉴, MT 날짜처럼 가벼운 의견을 모을 때 단톡방 채팅이나 손들기로 하면 표가 흩어지고, 누가 몇 번 말했는지 헷갈리고, 결과를 다시 찾아보기도 어렵다. 회장과 운영진은 질문 하나를 올리고 구성원이 선택지 하나씩 고르게 한 뒤 결과를 깔끔하게 보고 싶다. 동아리 밖 사람의 표가 섞이는 것도 막고 싶다.

## 해결책

카톡 링크로 휴대폰에서 바로 여는 한국어 웹앱을 만든다.

- 구성원은 공유된 입장 비밀번호를 한 번 입력하고 들어와서, 진행 중인 투표에서 선택지 하나를 골라 표를 남기고 결과를 본다.
- 관리자는 관리자 비밀번호로 들어와서 투표를 만들고, 마감하고, 필요하면 삭제한다.
- 마감된 투표도 결과와 함께 목록에 남아서 지난 결정을 다시 찾아볼 수 있다.

## 사용자 스토리

### 입장

1. 투표자로서, 나는 입장 비밀번호를 한 번 입력하면 앱에 들어가고 싶다, 동아리 구성원만 투표에 참여하도록 하기 위해
2. 투표자로서, 나는 입장 후 30일 동안 비밀번호를 다시 입력하지 않고 싶다, 카톡 링크를 눌러 가끔 들어올 때 번거롭지 않도록
3. 투표자로서, 나는 비밀번호를 틀리면 틀렸다는 안내를 받고 싶다, 다시 시도할 수 있도록
4. 입장하지 않은 방문자로서, 나는 투표 링크를 눌러도 입장 화면으로 안내되고 싶다, 먼저 비밀번호를 입력해야 한다는 걸 알 수 있도록
5. 입장하지 않은 방문자로서, 나는 어떤 투표 목록이나 결과도 볼 수 없어야 한다, 동아리 내부 투표가 밖으로 새지 않도록
6. 투표자로서, 나는 입장 후 원래 누르려던 투표 화면으로 바로 가고 싶다, 목록에서 다시 찾지 않아도 되도록

### 투표 목록

7. 투표자로서, 나는 진행 중인 투표를 목록 위쪽에서 최신순으로 보고 싶다, 지금 참여할 투표를 바로 찾기 위해
8. 투표자로서, 나는 마감된 투표를 목록 아래쪽에서 최신순으로 보고 싶다, 지난 결정을 다시 확인하기 위해
9. 투표자로서, 나는 이미 표를 남긴 투표에 "투표 완료" 표시를 보고 싶다, 어떤 투표를 아직 안 했는지 알기 위해
10. 투표자로서, 나는 투표가 하나도 없을 때 비어 있다는 안내를 보고 싶다, 앱이 고장 난 게 아니라는 걸 알기 위해

### 투표하기

11. 투표자로서, 나는 진행 중인 투표의 질문과 선택지를 보고 싶다, 무엇을 고를지 판단하기 위해
12. 투표자로서, 나는 선택지 중 정확히 하나를 골라 표를 남기고 싶다, 내 의견을 전달하기 위해
13. 투표자로서, 나는 표를 남기자마자 결과 화면을 보고 싶다, 다른 사람들의 선택을 확인하기 위해
14. 투표자로서, 나는 이미 표를 남긴 투표에 다시 들어가면 투표 화면 대신 결과를 보고 싶다, 같은 투표에 두 번 표를 남기지 않도록
15. 투표자로서, 나는 이미 남긴 표를 바꿀 수 없다는 걸 알고 싶다, 신중하게 고르기 위해
16. 투표자로서, 나는 입장 세션이 끝나 비밀번호를 다시 입력한 뒤에도 이전에 투표한 기록이 유지되길 원한다, "투표 완료" 표시가 사라지지 않도록
17. 투표자로서, 나는 마감된 투표에는 표를 남길 수 없어야 한다, 마감 이후의 표가 결과를 바꾸지 않도록
18. 투표자로서, 나는 투표 화면을 연 사이 투표가 마감되었다면 표를 남길 때 마감되었다는 안내를 받고 싶다, 왜 표가 반영되지 않았는지 알기 위해
19. 투표자로서, 나는 투표 화면을 연 사이 투표가 삭제되었다면 없어진 투표라는 안내를 받고 싶다, 헤매지 않도록

### 결과

20. 투표자로서, 나는 표를 남기기 전에는 진행 중인 투표의 결과를 볼 수 없어야 한다, 결과에 휩쓸리지 않고 고르기 위해
21. 투표자로서, 나는 선택지별 표 수와 비율(%)을 보고 싶다, 어느 쪽이 얼마나 앞서는지 알기 위해
22. 투표자로서, 나는 총 표 수를 보고 싶다, 몇 명이 참여했는지 알기 위해
23. 투표자로서, 나는 결과에서 내가 고른 선택지가 강조되어 보이길 원한다, 내 선택을 다시 확인하기 위해
24. 투표자로서, 나는 진행 중인 투표의 결과 화면을 보고 있으면 5초마다 숫자가 자동으로 갱신되길 원한다, 새로고침하지 않고 최신 결과를 보기 위해
25. 투표자로서, 나는 마감된 투표의 결과를 표를 남기지 않았어도 보고 싶다, 마감 후에는 투표할 방법이 없기 때문에
26. 투표자로서, 나는 결과를 보는 중에 투표가 마감되면 더 이상 갱신되지 않고 마감 상태가 표시되길 원한다, 최종 결과임을 알기 위해

### 관리자 입장

27. 관리자로서, 나는 관리자 전용 주소에서 관리자 비밀번호를 입력해 관리자가 되고 싶다, 투표를 관리하기 위해
28. 관리자로서, 나는 관리자 비밀번호만 입력하면 입장 비밀번호를 따로 입력하지 않아도 되길 원한다, 두 번 입력하지 않도록
29. 관리자로서, 나는 관리자 세션이 1일 뒤 끝나길 원한다, 공용 기기에 관리자 권한이 오래 남지 않도록
30. 관리자로서, 나는 로그아웃 버튼으로 관리자 세션을 바로 끝내고 싶다, 다른 사람 기기에서 썼을 때 권한을 지우기 위해
31. 관리자로서, 나는 투표 목록 화면 아래의 "관리자 로그인" 링크로 관리자 화면에 들어가고, 들어간 뒤에는 같은 자리에서 "관리자로 로그인됨" 표시와 관리자 화면 링크, 로그아웃을 보고 싶다, 주소를 외우지 않고 지금 관리자인지 알 수 있도록 (2026-09-25 변경: 처음에는 링크를 두지 않기로 했다)

### 투표 만들기

32. 관리자로서, 나는 질문 하나와 선택지 2~10개를 입력해 투표를 만들고 싶다, 구성원의 의견을 묻기 위해
33. 관리자로서, 나는 선택지 입력 칸을 추가하거나 지울 수 있길 원한다, 선택지 개수를 자유롭게 정하기 위해
34. 관리자로서, 나는 질문이 비었거나 100자를 넘으면 안내를 받고 싶다, 올바른 투표를 만들기 위해
35. 관리자로서, 나는 선택지가 비었거나 50자를 넘거나 서로 같은 문구면 안내를 받고 싶다, 헷갈리는 선택지를 만들지 않기 위해
36. 관리자로서, 나는 입력 앞뒤의 공백이 자동으로 지워지길 원한다, 공백 차이로 중복 검사가 빠지지 않도록
37. 관리자로서, 나는 투표를 만들면 바로 그 투표 화면으로 가고 싶다, 링크를 복사해 단톡방에 공유하기 위해
38. 관리자로서, 나는 만든 투표를 수정할 수 없다는 걸 알고 싶다, 오타가 있으면 삭제하고 다시 만들기 위해

### 투표 관리

39. 관리자로서, 나는 표를 남기지 않고도 진행 중인 투표의 결과를 보고 싶다, 마감 시점을 판단하기 위해
40. 관리자로서, 나는 일반 투표자처럼 표를 남길 수도 있길 원한다, 나도 동아리 구성원이기 때문에
41. 관리자로서, 나는 진행 중인 투표를 버튼 하나로 마감하고 싶다, 의견 수렴을 끝내기 위해
42. 관리자로서, 나는 마감한 투표를 다시 열 수 없다는 걸 알고 싶다, 마감이 최종 결정이 되도록
43. 관리자로서, 나는 진행 중이든 마감됐든 투표를 삭제하고 싶다, 실수로 만든 투표를 치우기 위해
44. 관리자로서, 나는 삭제 전에 "복구할 수 없다"는 확인 창을 보고 싶다, 실수로 지우지 않도록
45. 관리자로서, 나는 삭제한 투표와 그 표가 완전히 사라지길 원한다, 목록과 데이터에 흔적이 남지 않도록

### 운영

46. 관리자로서, 나는 입장 비밀번호를 바꾸면 기존에 입장한 모든 브라우저가 다시 비밀번호를 입력해야 하길 원한다, 비밀번호가 샜을 때 외부인을 내보내기 위해
47. 관리자로서, 나는 관리자 비밀번호를 바꾸면 기존 관리자 세션이 모두 끊기길 원한다, 관리자 비밀번호가 샜을 때 권한을 회수하기 위해
48. 투표자로서, 나는 비밀번호가 바뀌어 다시 입장해도 이전에 남긴 표가 그대로 인식되길 원한다, 비밀번호 교체 때문에 다시 투표할 수 있게 되지 않도록
49. 투표자로서, 나는 휴대폰 화면에서 모든 기능을 편하게 쓰고 싶다, 주로 카톡 링크로 들어오기 때문에

## 구현 결정 사항

### 스택과 배포

- Next.js 16 App Router, TypeScript. 서버 API는 Route Handler로 만든 REST API다. Server Actions는 쓰지 않는다.
- Neon Postgres에 `@neondatabase/serverless` 드라이버로 SQL을 직접 작성한다. ORM은 쓰지 않는다. 스키마는 SQL 파일 하나로 관리하고 수동으로 적용한다.
- Vercel에 배포한다. 환경변수는 다음 네 가지다.

| 환경변수 | 용도 |
| --- | --- |
| `DATABASE_URL` | Neon 연결 문자열 (로컬 `.env.local`에 이미 있음) |
| `ENTRY_PASSWORD` | 입장 비밀번호 |
| `ADMIN_PASSWORD` | 관리자 비밀번호 |
| `SESSION_SECRET` | 세션 쿠키 서명용 비밀 값 |

- 이 Next.js 버전은 학습 데이터와 다르다. 구현 전에 `node_modules/next/dist/docs/`의 관련 가이드를 읽는다. 특히 Next.js 16에서 `middleware`는 `proxy`로 이름이 바뀌었고, `proxy`는 Node.js 런타임에서 실행된다.

### 데이터베이스 스키마

테이블은 투표(`polls`), 선택지(`options`), 표(`votes`) 세 개다.

**`polls` (투표)**

| 열 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| `id` | uuid | PK, 기본값 무작위 생성 | 투표 링크에 쓰인다 |
| `question` | text | NOT NULL, 1~100자 | 질문 |
| `status` | text | NOT NULL, `'open'` 또는 `'closed'`, 기본값 `'open'` | 진행 중 / 마감 |
| `created_at` | timestamptz | NOT NULL, 기본값 현재 시각 | 목록 정렬 기준 |
| `closed_at` | timestamptz | NULL 허용 | 마감 시각. `status`가 `'closed'`일 때만 값이 있다 |

**`options` (선택지)**

| 열 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| `id` | uuid | PK | |
| `poll_id` | uuid | NOT NULL, FK → `polls.id`, 투표 삭제 시 함께 삭제 | |
| `label` | text | NOT NULL, 1~50자 | 선택지 문구 |
| `position` | integer | NOT NULL | 화면 표시 순서(0부터) |

- 유니크: (`poll_id`, `label`), (`poll_id`, `position`), (`id`, `poll_id`). 마지막 제약은 표가 같은 투표의 선택지만 가리키도록 복합 FK를 걸기 위한 것이다.

**`votes` (표)**

| 열 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| `id` | uuid | PK | |
| `poll_id` | uuid | NOT NULL, FK → `polls.id`, 투표 삭제 시 함께 삭제 | |
| `option_id` | uuid | NOT NULL | |
| `voter_id` | text | NOT NULL | 브라우저 식별 쿠키 값 |
| `created_at` | timestamptz | NOT NULL, 기본값 현재 시각 | |

- 복합 FK: (`option_id`, `poll_id`) → `options`(`id`, `poll_id`). 다른 투표의 선택지에 표를 남길 수 없다.
- 유니크: (`poll_id`, `voter_id`). **1인 1표의 최종 보장은 이 제약이다.** 동시에 두 번 요청해도 하나만 저장된다.
- 투표자를 사람 단위로 식별하는 정보(이름, 이메일, IP)는 저장하지 않는다.

**데이터 규칙**

- 투표 생성은 투표 1건과 선택지 2~10건을 한 트랜잭션으로 저장한다.
- 표 저장은 "투표가 진행 중일 때만" 조건을 같은 쿼리 안에서 확인한다. 마감 요청과 투표 요청이 동시에 와도 마감 이후의 표가 저장되지 않게 하기 위해서다.
- 마감은 `status`를 `'closed'`로, `closed_at`을 현재 시각으로 바꾼다. `'closed'`에서 `'open'`으로 바꾸는 경로는 없다.
- 투표를 삭제하면 선택지와 표가 연쇄 삭제된다.

### 쿠키와 세션

쿠키 세 개를 서로 독립적으로 관리한다. 모두 `HttpOnly`, `SameSite=Lax`, 운영 환경에서 `Secure`다.

| 쿠키 | 수명 | 발급 시점 | 내용 |
| --- | --- | --- | --- |
| 브라우저 식별 쿠키 | 1년 | 입장하거나 관리자로 들어올 때 없으면 발급 | 무작위 `voter_id` |
| 입장 세션 쿠키 | 30일 | 입장 비밀번호 확인 성공 | 서명된 토큰 |
| 관리자 세션 쿠키 | 1일 | 관리자 비밀번호 확인 성공 | 서명된 토큰 |

- 세션 토큰은 만료 시각을 담고, `SESSION_SECRET`을 키로 세션 종류·만료 시각·해당 비밀번호를 함께 서명한다. 비밀번호를 바꾸면 서명이 맞지 않아 기존 세션이 모두 무효가 된다.
- 브라우저 식별 쿠키는 비밀번호와 무관하다. 입장 세션이 끝나거나 비밀번호가 바뀌어도 유지되어 이전 표가 계속 인식된다.
- 관리자 세션이 유효하면 입장 세션도 유효한 것으로 본다.
- 비밀번호 비교는 타이밍 공격에 안전한 방식으로 한다.

### 접근 제어

- `proxy`에서 입장 세션(또는 관리자 세션)을 확인한다. 입장 화면과 입장 API, 관리자 로그인 화면과 로그인 API, 정적 파일만 예외다.
- 입장하지 않은 요청은 화면이면 입장 화면으로 보내고(원래 주소를 쿼리로 넘겨 입장 후 되돌아간다), API면 401을 돌려준다.
- 관리자 전용 API는 Route Handler 안에서 관리자 세션을 다시 확인하고, 없으면 403을 돌려준다. 화면의 버튼 숨김에만 의존하지 않는다.

### 화면

| 경로 | 화면 | 접근 |
| --- | --- | --- |
| `/enter` | 입장 비밀번호 입력 | 누구나 |
| `/` | 투표 목록 (진행 중 섹션 위, 마감 섹션 아래, 각각 최신순, "투표 완료" 표시) | 입장 |
| `/polls/[id]` | 투표 상세. 상태에 따라 투표 폼 또는 결과를 보여준다. 관리자에게는 결과, 마감, 삭제 버튼도 보인다 | 입장 |
| `/admin` | 관리자 비밀번호 입력. 이미 관리자면 투표 만들기 버튼과 로그아웃 | 누구나 |
| `/polls/new` | 투표 만들기 폼 | 관리자 |

- 투표 상세 화면이 보여줄 것: 진행 중이고 표가 없으면 투표 폼(관리자는 투표 폼 아래 결과도 보인다), 진행 중이고 표가 있으면 결과, 마감이면 결과.
- 결과는 진행 중인 투표에서만 5초마다 결과 API를 다시 불러 갱신한다. 응답이 마감 상태면 갱신을 멈춘다.
- UI는 한국어, 모바일 우선이다.

### API 계약

모든 응답은 JSON이다. 오류 응답은 `{ "error": "<코드>", "message": "<한국어 안내>" }` 형태다. 표에 코드 없이 적힌 403은 `forbidden`(관리자 아님)이다.

| 메서드와 경로 | 권한 | 요청 | 성공 응답 | 실패 |
| --- | --- | --- | --- | --- |
| `POST /api/entry` | 누구나 | `{ password }` | 204, 입장 세션 쿠키와 (없으면) 브라우저 식별 쿠키 발급 | 401 `wrong_password` |
| `POST /api/admin/session` | 누구나 | `{ password }` | 204, 관리자 세션 쿠키와 (없으면) 브라우저 식별 쿠키 발급 | 401 `wrong_password` |
| `DELETE /api/admin/session` | 누구나 | 없음 | 204, 관리자 세션 쿠키 삭제 | |
| `GET /api/polls` | 입장 | 없음 | 200 `{ open: PollSummary[], closed: PollSummary[] }`, 각각 최신순 | |
| `POST /api/polls` | 관리자 | `{ question, options: string[] }` | 201 `{ id }` | 400 `invalid_input`(필드별 사유 포함), 403 |
| `GET /api/polls/[id]` | 입장 | 없음 | 200 `PollDetail` | 404 `not_found` |
| `POST /api/polls/[id]/votes` | 입장 | `{ optionId }` | 201 `Result` | 400 `invalid_option`, 404, 409 `already_voted`, 409 `poll_closed` |
| `GET /api/polls/[id]/result` | 입장 | 없음 | 200 `Result` | 403 `result_hidden`, 404 |
| `POST /api/polls/[id]/close` | 관리자 | 없음 | 200 `PollDetail` | 403, 404, 409 `already_closed` |
| `DELETE /api/polls/[id]` | 관리자 | 없음 | 204 | 403, 404 |

응답 형태:

- `PollSummary`: `id`, `question`, `status`, `createdAt`, `hasVoted`(이 브라우저 기준)
- `PollDetail`: `id`, `question`, `status`, `createdAt`, `closedAt`, `options`(`id`, `label`을 `position` 순서로), `myOptionId`(표가 없으면 `null`), `canViewResult`, `isAdmin`
- `Result`: `pollId`, `status`, `totalVotes`, `options`(`id`, `label`, `votes`, `percent`를 `position` 순서로), `myOptionId`

### 투표 규칙 모듈 (테스트 심)

도메인 규칙은 DB와 HTTP를 모르는 순수 함수 모듈 하나에 모은다. Route Handler는 입력을 읽고, DB에서 상태를 가져와 이 모듈에 묻고, 그 답대로 저장하거나 응답만 한다.

- **투표 입력 검증**: 질문과 선택지 목록을 받아 앞뒤 공백을 지운 값 또는 필드별 오류 목록을 돌려준다. 규칙: 질문 1~100자, 선택지 2~10개, 각 1~50자, 공백 제거 후 서로 다른 문구.
- **투표 가능 여부**: 투표 상태, 이 브라우저의 기존 표 여부, 고른 선택지가 이 투표에 속하는지를 받아 허용 또는 거부 사유(`poll_closed`, `already_voted`, `invalid_option`)를 돌려준다.
- **결과 공개 여부**: 투표 상태, 이 브라우저의 표 여부, 관리자 여부를 받아 볼 수 있는지 돌려준다. 규칙: 관리자이거나, 표를 남겼거나, 마감된 투표면 볼 수 있다.
- **결과 집계**: 선택지 목록과 선택지별 표 수를 받아 총 표 수와 선택지별 비율을 계산한다. 비율은 정수로 반올림하며(합계가 100이 아닐 수 있다), 총 표 수가 0이면 모두 0%다.

규칙 모듈이 거부하더라도 DB 제약(1인 1표 유니크, 진행 중 조건부 저장, 복합 FK)이 최종 방어선이다. 동시 요청으로 DB 제약에 걸리면 규칙 모듈의 거부 사유와 같은 오류 코드로 응답한다.

## 테스트 결정 사항

- 테스트 도구는 Vitest다. 아직 설치되어 있지 않으므로 개발 의존성으로 추가하고 `test` 스크립트를 만든다.
- 테스트 대상은 **투표 규칙 모듈** 하나다. 네 가지 규칙 함수를 공개 인터페이스로만 호출하고, 입력에 대한 결과(허용/거부 사유, 공개 여부, 검증 오류, 집계 값)만 확인한다. 내부 구현 방식은 테스트하지 않는다.
- 반드시 포함할 경우:
  - 입력 검증: 질문 빈 칸/공백만/100자/101자, 선택지 1개/2개/10개/11개, 선택지 50자/51자, 공백 차이만 있는 중복(`"치킨"`과 `" 치킨 "`), 공백 제거 결과
  - 투표 가능 여부: 진행 중이고 처음 투표함, 이미 투표함, 마감됨, 다른 투표의 선택지
  - 결과 공개 여부: 진행 중에 표 없음(비공개), 진행 중에 표 있음, 마감 후 표 없음, 관리자, 이 조합들
  - 결과 집계: 표 0개, 한 선택지에 몰림, 반올림 경계(예: 3표를 1:1:1로 나눔), 표가 없는 선택지 포함
- DB, Route Handler, 화면은 자동 테스트하지 않는다. DB 제약은 코드 리뷰로 확인하고, 화면과 흐름은 아래 성공 기준을 기준으로 직접 눌러 확인한다.
- 코드베이스에 기존 테스트가 없어서 참고할 선행 사례는 없다. 이 스펙의 규칙 모듈 테스트가 첫 사례가 된다.

## 성공 기준

**자동 확인**

- [ ] 투표 규칙 모듈 테스트가 모두 통과한다.
- [ ] 린트와 프로덕션 빌드가 오류 없이 끝난다.

**직접 확인 (Vercel 배포본, 휴대폰 브라우저 기준)**

- [ ] 입장하지 않은 상태로 투표 링크를 열면 입장 화면이 나오고, 올바른 비밀번호를 입력하면 원래 투표 화면으로 간다.
- [ ] 입장하지 않은 상태에서 API를 직접 호출하면 401이 돌아온다.
- [ ] 관리자가 질문 하나와 선택지 3개로 투표를 만들 수 있고, 규칙에 어긋나는 입력은 안내와 함께 거부된다.
- [ ] 투표자가 선택지 하나를 고르면 결과 화면으로 넘어가고, 표 수, 비율, 총 표 수, 내 선택 강조가 보인다.
- [ ] 같은 브라우저로 같은 투표에 다시 표를 남길 수 없다. 입장 세션 쿠키만 지우고 다시 입장해도 마찬가지다.
- [ ] 다른 브라우저(시크릿 창)에서는 표를 하나 더 남길 수 있다(의도된 동작).
- [ ] 두 기기에서 같은 투표 결과 화면을 열어 두고 한쪽에서 투표하면, 다른 쪽 숫자가 5초 안에 바뀐다.
- [ ] 표를 남기지 않은 투표자는 진행 중인 투표의 결과를 볼 수 없고, 관리자는 볼 수 있다.
- [ ] 관리자가 마감하면 투표가 목록의 마감 섹션으로 옮겨지고, 표를 남기지 않은 투표자도 결과를 볼 수 있으며, 더 이상 표를 남길 수 없다.
- [ ] 관리자가 삭제하면 확인 창이 뜨고, 확인 후 목록에서 사라지며, 그 투표 링크는 없는 투표로 안내된다.
- [ ] 관리자 로그아웃 후에는 관리자 기능을 쓸 수 없다.
- [ ] 목록에 진행 중과 마감 섹션이 나뉘어 최신순으로 보이고, 투표한 항목에 "투표 완료"가 표시된다.

## 범위 외

이번 버전에서 만들지 않는다.

- **자동 마감**: 마감 일시를 정해 두면 저절로 마감되는 기능. 관리자가 버튼으로 하는 **수동 마감은 범위에 포함된다.**
- **결과 그래프**: 막대그래프 등 시각화. 이번에는 표 수와 비율만 숫자로 보여준다. 다음 버전에서 추가할 예정이다.
- **표 변경과 취소**: 한 번 남긴 표는 바꾸거나 취소할 수 없다.
- **투표 수정**: 만든 뒤 질문이나 선택지를 고칠 수 없다.
- **마감 후 다시 열기**
- **삭제 복구, 숨김 처리**: 삭제는 완전 삭제만 있다.
- **개인 로그인, 회원 명단, 소셜 로그인**: [ADR 0001](../../docs/adr/0001-shared-passwords-and-cookie-voting.md) 참고.
- **브라우저를 넘는 중복 투표 방지**: 시크릿 창이나 다른 기기로 다시 투표하는 것은 막지 않는다.
- **누가 무엇을 골랐는지 보기**: 표는 익명이며 투표자 명단을 보여주지 않는다.
- **여러 선택지 동시 선택, 순위 투표, 기타(직접 입력) 선택지**
- **실시간 푸시(WebSocket 등)**: 5초 폴링으로 대신한다.
- **투표 설명 문구, 이미지 첨부**
- **다국어 지원**: 한국어만 지원한다.
- **알림(카톡, 이메일, 푸시)**
- **공정성이 중요한 선거**: 이 앱의 용도가 아니다.

## 추가 참고 사항

- 사용 규모는 50명 이하 동아리다. 성능 최적화나 캐싱은 신경 쓰지 않는다. 목록과 결과는 요청마다 DB에서 새로 읽는다.
- 결과 공개 규칙은 화면이 아니라 서버(결과 API와 투표 상세 API)에서 판단한다. 화면에서 숨기기만 하면 API로 결과를 볼 수 있기 때문이다.
- 스키마 SQL은 Neon에 수동으로 한 번 적용한다. 마이그레이션 도구는 쓰지 않는다.
- Vercel 환경변수 설정(`ENTRY_PASSWORD`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `DATABASE_URL`)은 사람이 직접 해야 하는 단계다.
