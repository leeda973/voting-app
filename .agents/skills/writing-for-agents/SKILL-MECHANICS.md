# 스킬 메커니즘

[`writing-for-agents`](SKILL.md)의 스킬 전용 분기다. 문서가 스킬일 때 무엇이 달라지는지(frontmatter, 호출 방식 선택, 라우터 스킬)를 다룬다. 스킬 작성에 관한 나머지 전부는 `SKILL.md`의 범용 참조에 있다.

## 호출

두 가지 선택지가 있으며, 두 부하를 맞바꾼다.

- **모델 호출(model-invoked)** 스킬은 `description`을 유지하므로 에이전트가 자율적으로 촉발할 수 있고, 다른 스킬도 도달할 수 있다. 여전히 이름을 입력해 호출할 수도 있다. 모델 호출은 항상 사용자의 접근을 _포함_한다. description은 에이전트의 발견 가능성을 더할 뿐, 사람의 접근을 빼앗지 않는다. description은 스킬의 최상위 컨텍스트 포인터이며, 항상 로드된 상태로 있어야 한다. 발견 가능성을 대가로 영구적인 컨텍스트 부하를 치르는 것이다. 내용이 전부 참조인 모델 호출 스킬은 공유 참조의 보금자리가 되기도 한다. 다른 스킬이 호출할 수 있으므로, 여러 스킬이 필요로 하는 참조가 한 곳에 산다. 메커니즘: `disable-model-invocation`을 생략하고, 촉발 분기를 담은 모델용 description을 쓴다(`SKILL.md`의 포인터 작성 규칙이 그대로 적용된다).
- **사용자 호출(user-invoked)** 스킬은 description을 에이전트의 손이 닿지 않게 한다. 이름을 입력하는 사람만 호출할 수 있고, 다른 어떤 스킬도 호출할 수 없다. 컨텍스트 부하는 0이지만 인지 부하를 쓴다. 그것이 존재한다는 것을 기억해야 하는 색인이 바로 당신이다. 메커니즘: `disable-model-invocation: true`를 설정한다. `description`은 사람용이 된다. 한 줄 요약이며, 촉발어 목록은 뺀다.

에이전트가 스스로 스킬에 도달해야 하거나, 다른 스킬이 도달해야 할 때만 모델 호출을 고른다. 손으로만 촉발된다면 사용자 호출로 만들고 컨텍스트 부하를 치르지 않는다.

두 사용자 호출 스킬이 모두 필요로 하는 공유 참조는 둘 중 어디에도 둘 수 없다. description이 없으니 어느 쪽도 다른 쪽을 촉발할 수 없다. 스킬 시스템 밖의 일반 파일로 밀어낸다. 어떤 스킬이든 가리킬 수 있는 외부 참조다.

## 호출 기준으로 나누기

나누기의 호출 기준(순서 기준은 `SKILL.md`에 있다): 스스로 스킬을 촉발해야 할 구별되는 핵심어(프롬프트에서 실제로 쓰는 촉발어)가 있거나, 다른 스킬이 도달해야 할 때 모델 호출 스킬로 떼어낸다. 새로 항상 로드되는 description에 대해 컨텍스트 부하를 치르므로, 그 독립적인 도달 가능성이 그만한 가치가 있어야 한다.

## 라우터 스킬

사용자 호출 스킬이 기억할 수 있는 수준을 넘어 늘어나면, 그렇게 쌓인 인지 부하는 **라우터 스킬(router skill)**로 해결한다. 다른 스킬들과 각각을 언제 찾아야 하는지를 나열하는 하나의 사용자 호출 스킬로, 사람은 여러 개 대신 스킬 하나만 기억하면 된다. 라우터는 힌트만 줄 수 있고 스킬을 촉발할 수는 없다. 사용자 호출 스킬에는 description이 없으므로, 사람 말고는 아무도 도달할 수 없다.
