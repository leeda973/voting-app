사용자가 **회고**(retrospective)를 요청했다. 당신은 이후 실행을 개선하기 위해 코딩 에이전트의 **환경**에 대한 개선안을 제안한다.

## 단계

1. 글쓰기 스타일 가이드를 위해 `writing-for-agents`로 Skill 도구를 호출한다.

2. 사용자가 지정한 세션의 1차 자료를 읽는다. 이 머신의 세션 로그를 검색해야 할 수도 있다. 사용자가 세션을 지정하지 않으면 현재 세션을 기본으로 한다.

3. 다음 범주에서 개선 후보를 찾는다.

- **탐색(Navigation)**: 에이전트가 올바른 파일을 찾기가 얼마나 쉬웠는가? 파일 사이에 숨겨진 의존성이 있는가? **탐색 포인터**(navigation pointer)가 있으면 더 쉬워지겠는가? _사용 시점:_ 세션에서 어떤 정보를 찾는 데 오랜 시간이 걸렸을 때.
- **자동화된 검사**: 에이전트가 저지른 오류를 잡아낼 수 있는 자동화된 검사가 있는가? 린팅, 타입 검사, 테스트, 파일 시스템 린터? 먼저 저장소 자체의 검사 명령(`package.json`/빌드 도구의 `lint`/`check` 스크립트, CI 워크플로)을 읽어라. 이미 존재하지만 연결되지 않았거나 조용히 깨져 있는 검사가 있다면 그것이 발견 사항이며, 새로 발명할 필요는 없다. **가드레일**(guardrail)이 없는 저장소(lint/typecheck/test 명령을 실행하는 pre-commit 훅도 CI 잡도 없는 저장소)는 그 자체로 발견 사항이다. 린트되지 않는 저장소는 중립적인 기본값이 아니라 상시 놓치고 있는 기회다. _사용 시점:_ 자동화된 검사로 잡을 수 있었던 실수를 에이전트가 했거나, 저장소에 가드레일이 전혀 없을 때.
- **코딩 표준**: **리뷰어 에이전트**에게 새로 강제할 규칙을 줘야 하는가? 기존 규칙을 제거하거나 명확히 해야 하는가? 먼저 위반을 분류한다. **기계적인** 위반(고정된 구문 패턴, 금지된 API, import 형태, 파일 위치 규칙)은 무조건 결정적(deterministic) 검사로 처리한다. 저장소 자체 린터의 커스텀 규칙, 새 pre-commit 훅, 새 CI 잡 중에서 저장소의 언어와 기존 가드레일상 가장 저렴한 방법을 택한다. 규칙을 글로 쓰기보다 검사를 만드는 것을 기본으로 한다. `CODING_STANDARDS.md`는 진정한 **판단이 필요한 사항**(파일 간 일관성, "주변 스타일과 일치하는가", 어떤 가드레일로도 대체할 수 없는 것)을 위해 남겨둔다. _사용 시점:_ 리뷰어 에이전트가 실수를 잡아내지 못했을 때.
- **전역 AGENTS.md**: 코딩 표준(또는 자동화된 검사)으로 옮겨야 할 조정 지침이 있는가? _사용 시점:_ AGENTS.md 파일이 특히 클 때 - 저장소 안이든 사용자의 전역 범위든.
- **도구 경제성**: 에이전트가 간소화할 수 있는 비싼 도구 호출을 했는가? 특히 토큰 효율이 나쁜 커스텀 도구(CLI, MCP)가 있는가? _사용 시점:_ 에이전트가 비싼 도구 호출을 했을 때.
- **무효 지침(No-ops)**: 조정 파일에서 에이전트의 행동을 바꾸지 않는 지침을 찾는다. _사용 시점:_ 조정 파일이 크고 다루기 힘들 때.
- **정보 접근**: 에이전트의 정보 접근성을 높일 기회를 찾는다. 개발 서버 로그를 tee로 남기기, 서드파티 서비스에 대한 읽기 전용 접근 등. _사용 시점:_ 결정적인 정보를 에이전트가 사용할 수 없었을 때.

4. 이 후보들을 심각도 순으로 사용자에게 제시한다.

## 참고

### 구현 vs 리뷰

모든 작업은 구현과 리뷰라는 두 단계를 거친다는 점을 기억하라. 구현 에이전트는 가장 큰 **컨텍스트 압박**(context pressure)을 받는다. 탐색, 코드 작성, 실패 디버깅을 모두 책임지기 때문이다.

리뷰 에이전트는 컨텍스트 압박이 가장 작다. diff를 받으므로 탐색이 필요 없다. 코드를 작성하거나 디버깅할 필요도 대개 없다.

따라서 코딩 표준을 강제하는 책임은 구현 에이전트가 아니라 리뷰 에이전트에게 있어야 한다.

### 파일

저장소에서 접근할 수 있는 파일은 다음과 같다.

- `CLAUDE.md`/`AGENTS.md`: 이 저장소에서 작업하는 모든 에이전트의 컨텍스트 창에 주입되는 파일이다. 매우 아껴서 사용해야 하며, 보통 다른 파일로 향하는 **탐색 포인터**에만 쓴다.
- `CODING_STANDARDS.md`: 이 파일은 구현이 아니라 리뷰 중에 읽힌다. 표준 파일이 1,000줄을 넘으면 docs 폴더로 향하는 **탐색 포인터**를 추가한다.
- Docs: 다른 파일이 가리키는 참고 파일로 docs를 사용한다. 새로 작성하기 전에 기존 docs를 찾아본다.
- Skills: 문서 용도(설명이 에이전트의 컨텍스트 창에 들어가므로)나 사용자가 호출하는 명령에 skill을 사용한다. `writing-for-agents` skill의 조언을 따른다.
