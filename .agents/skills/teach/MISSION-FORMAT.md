# MISSION.md 형식

`MISSION.md`는 워크스페이스 루트에 둔다. 사용자가 이 주제를 배우는 *이유*를 담는다. 모든 교육적 결정(다음에 무엇을 가르칠지, 어떤 자료를 보여 줄지, 어떤 연습 문제를 설계할지)은 이 문서로 거슬러 올라갈 수 있어야 한다.

## 템플릿

```md
# 미션: {Topic}

## 이유
{1-3문장. 사용자가 좇는 구체적인 현실 목표. 이 기술을 갖추면 삶이나 일에서 무엇이 달라지는가? "X를 이해하기 위해" 같은 추상적인 표현은 피하고, 그 밑에 있는 결과를 끌어내라.}

## 성공의 모습
- {사용자가 할 수 있게 될 구체적이고 관찰 가능한 일}
- {또 다른 구체적인 일}
- {…}

## 제약
- {시간, 예산, 기존 약속, 학습 선호도 등 접근 방식을 제한하는 모든 것}

## 범위 외
- {사용자가 지금은 명시적으로 좇고 싶지 않은 인접 주제. 근접 발달 영역을 보호한다}
```

## 규칙

- **워크스페이스당 미션 하나.** 사용자가 서로 관련 없는 두 가지를 배우고 싶다면, 워크스페이스도 두 개다.
- **추상보다 구체.** "10월까지 하프 마라톤 완주"가 "더 건강해지기"보다 낫다. "우리 팀에 Rust CLI 배포하기"가 "Rust 배우기"보다 낫다.
- **모호함에는 반박하라.** 사용자가 이유를 분명히 말하지 못한다면, 무엇이든 쓰기 전에 인터뷰하라. 나쁜 미션은 미션이 없는 것보다 나쁘다.
- **현실이 바뀌면 수정하라.** 미션은 변한다. 사용자의 목표가 옮겨 가면 이 파일을 갱신하라. 낡은 미션이 앞으로의 세션을 이끌게 두지 마라.
- **짧게 유지하라.** `MISSION.md`가 한 화면을 넘어가면, 나침반이 아니라 계획서가 되어 버린 것이다.
