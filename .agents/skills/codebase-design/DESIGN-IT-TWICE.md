# 두 번 설계하라(Design It Twice)

사용자가 선택한 심화 후보에 대해 대안 인터페이스를 탐색하고 싶어 할 때, 이 병렬 서브에이전트 패턴을 사용하라. Ousterhout의 "Design It Twice"에 기반한다. 첫 아이디어가 최선일 가능성은 낮다.

[SKILL.md](SKILL.md)의 어휘를 사용한다: **모듈(module)**, **인터페이스(interface)**, **심(seam)**, **어댑터(adapter)**, **레버리지(leverage)**.

## 프로세스

### 1. 문제 공간 정의

서브에이전트를 실행하기 전에, 선택한 후보의 문제 공간을 사용자에게 보여 줄 설명으로 작성하라:

- 새 인터페이스가 충족해야 할 제약 조건
- 의존하게 될 의존성과 그것이 속한 범주([DEEPENING.md](DEEPENING.md) 참고)
- 제약 조건을 구체화하기 위한 대략적인 예시 코드 스케치. 제안이 아니라, 제약 조건을 구체적으로 만드는 수단일 뿐이다

이것을 사용자에게 보여 준 뒤 즉시 2단계로 진행하라. 서브에이전트들이 병렬로 작업하는 동안 사용자는 읽고 생각한다.

### 2. 서브에이전트 실행

3개 이상의 서브에이전트를 병렬로 실행하라. 각각은 심화된 모듈에 대해 **근본적으로 다른** 인터페이스를 만들어야 한다.

각 서브에이전트에게 별도의 기술 지시서를 프롬프트로 줘라(파일 경로, 결합 세부 사항, [DEEPENING.md](DEEPENING.md)의 의존성 범주, 심 뒤에 무엇이 있는지). 이 지시서는 1단계의 사용자용 문제 공간 설명과 별개다. 각 에이전트에게 서로 다른 설계 제약을 줘라:

- 에이전트 1: "인터페이스를 최소화하라. 진입점은 최대 1–3개를 목표로 하라. 진입점당 레버리지를 극대화하라."
- 에이전트 2: "유연성을 극대화하라. 많은 사용 사례와 확장을 지원하라."
- 에이전트 3: "가장 흔한 호출자에 최적화하라. 기본 사례를 아주 간단하게 만들어라."
- 에이전트 4 (해당하는 경우): "심을 가로지르는 의존성에 대해 포트와 어댑터(ports & adapters)를 중심으로 설계하라."

지시서에 [SKILL.md](SKILL.md) 어휘와 CONTEXT.md 어휘를 모두 포함하여, 각 서브에이전트가 아키텍처 언어 및 프로젝트의 도메인 언어와 일관되게 이름을 짓게 하라.

각 서브에이전트의 출력:

1. 인터페이스(타입, 메서드, 매개변수, 그리고 불변 조건, 순서, 오류 모드)
2. 호출자가 어떻게 사용하는지 보여 주는 사용 예시
3. 구현이 심 뒤에 숨기는 것
4. 의존성 전략과 어댑터([DEEPENING.md](DEEPENING.md) 참고)
5. 트레이드오프: 레버리지가 높은 곳과 얇은 곳

### 3. 제시와 비교

사용자가 각각을 소화할 수 있도록 설계를 순차적으로 제시한 뒤, 산문으로 비교하라. **깊이(depth)** (인터페이스에서의 레버리지), **지역성(locality)** (변경이 집중되는 곳), **심 배치**로 대조하라.

비교한 뒤에는 자신의 추천을 제시하라. 어떤 설계가 가장 강력하다고 생각하는지와 그 이유. 서로 다른 설계의 요소들이 잘 결합된다면 하이브리드를 제안하라. 분명한 의견을 가져라. 사용자는 메뉴가 아니라 확실한 판단을 원한다.
