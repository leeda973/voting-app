# GLOSSARY.md 형식

`GLOSSARY.md`는 이 학습 워크스페이스의 표준 언어다. 모든 설명 자료, 연습 문제, 학습 기록은 이 용어를 따라야 한다. 용어집을 만드는 것 자체가 학습의 일부다. 개념을 간결한 정의로 압축할 수 있다는 것은 사용자가 그것을 이해했다는 증거다.

## 구조

```md
# {Topic} 용어집

{이 용어집이 다루는 주제를 한두 문장으로 설명.}

## 용어

**근비대(Hypertrophy)**:
반복되는 훈련 세션에 걸친 기계적 장력과 대사 스트레스로 일어나는 근육 성장.
_피할 표현_: 벌크업, 몸 키우기

**점진적 과부하(Progressive overload)**:
부하, 볼륨, 강도를 통해 시간에 따라 근육에 가해지는 요구를 체계적으로 늘리는 것.
_피할 표현_: 더 세게 밀어붙이기, 레벨업

**RPE (Rate of Perceived Exertion, 자각적 운동 강도)**:
한 세트가 얼마나 힘들었는지를 1–10으로 매기는 자기 평가. 10은 실패 지점이고 8은 두 번 더 할 여력이 남았다는 뜻이다.
_피할 표현_: 노력 점수, 강도 등급
```

## 규칙

- **사용자가 이해했을 때만 용어를 추가하라.** 용어집은 압축된 지식의 기록이지, 사용자가 배우려고 읽는 사전이 아니다. 사용자가 방금 개념을 접했다면, 그것을 올바르게 사용할 수 있을 때까지 기다렸다가 여기에 올려라.
- **분명한 입장을 가져라.** 같은 개념에 여러 단어가 있다면 가장 좋은 것 하나를 고르고 나머지는 피할 별칭으로 나열하라. 이것이 언어가 압축되는 방식이다.
- **정의를 간결하게 유지하라.** 한두 문장. 그 용어가 무엇을 하는지나 어떻게 하는지가 아니라, 그것이 무엇인지를 정의하라.
- **정의 안에서도 용어집의 용어를 사용하라.** 어떤 용어가 용어집에 들어가면, 다른 정의 안을 포함해 모든 곳에서 그 용어를 우선하라. 이렇게 해야 나중에 복잡한 용어를 파악하기 쉬워진다.
- 자연스러운 묶음이 생기면 **소제목 아래로 그룹화하라**(예: `## Anatomy`, `## Programming`). 용어들이 서로 잘 어울린다면 평평한 목록도 괜찮다.
- **모호함은 명시적으로 표시하라.** 어떤 용어가 해당 분야 전반에서 느슨하게 쓰인다면, 여기서 어떻게 정했는지 적어라: "이 워크스페이스에서 'set'은 항상 본 세트를 뜻하며, 워밍업은 따로 기록한다."
- **이해가 깊어지면 수정하라.** 사용자가 첫 주에 쓴 정의는 여섯째 주에는 틀렸을 수 있다. 그 자리에서 고치고, 낡은 항목을 남겨 두지 마라.
