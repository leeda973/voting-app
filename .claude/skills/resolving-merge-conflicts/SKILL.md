---
name: resolving-merge-conflicts
description: "진행 중인 git merge/rebase 충돌을 해결해야 할 때 사용한다."
---

1. merge/rebase의 **현재 상태를 파악한다**. git 히스토리와 충돌이 난 파일을 확인한다.

2. 각 충돌의 **1차 자료를 찾는다**. 각 변경이 왜 이루어졌는지, 원래 의도가 무엇이었는지 깊이 이해한다. 커밋 메시지를 읽고, PR을 확인하고, 원본 이슈/티켓을 확인한다.

3. **각 hunk를 해결한다.** 가능하면 양쪽의 의도를 모두 보존한다. 서로 양립할 수 없다면 merge가 밝힌 목표에 맞는 쪽을 선택하고 그 트레이드오프를 기록한다. 새로운 동작을 **지어내지 않는다**. 항상 해결하며, 절대 `--abort`하지 않는다.

4. 프로젝트의 **자동화된 검사**를 찾아 실행한다. 보통 typecheck, 그다음 테스트, 그다음 포맷 순이다. merge로 인해 깨진 것은 모두 고친다.

5. **merge/rebase를 마무리한다.** 모든 변경을 stage하고 커밋한다. rebase 중이라면 모든 커밋이 rebase될 때까지 rebase 과정을 계속한다.
