# 마법사(Wizard)

**마법사(wizard)**는 손으로 하기 번거롭고 매번 AI에게 다시 설명하기도 번거로운 수동 절차를 사람에게 단계별로 안내하는 bash 스크립트다. 각 URL을 열고, 무엇을 클릭하고 복사할지 정확히 알려주고, 값을 받아서 알맞은 곳(`.env`, GitHub 시크릿)에 기록하고, 단계마다 확인을 받고, 남은 단계 수를 보여준다. 서드파티 서비스를 설정하거나, 일회성 마이그레이션을 실행하거나, 프로젝트를 한 상태에서 다른 상태로 옮길 수 있다.

쾌적한 UX는 이미 [template.sh](template.sh)가 해결해 두었다. 단계별 진행 표시, 확인 게이트, (WSL을 포함한) 크로스 플랫폼 URL 열기, 숨김 시크릿 입력, 멱등적인 `.env` upsert, `gh secret`/`gh variable` 기록, 마무리 요약. **당신의 일은 절차의 범위를 정하고 단계를 작성하는 것뿐이다.** `STAGES` 마커 위의 라이브러리는 모든 마법사에서 동일하며, 그 일관성이 핵심이다. 절대 직접 수정하지 않는다.

마법사는 기본적으로 일회용이다. 한 번 실행하려고 만들어 스크래치 경로나 `scripts/` 경로에 저장하고, 일이 끝나면 삭제한다. 사용자가 저장소에 남아야 할 반복 가능한 설정 경로를 원할 때만 커밋한다.

## 절차

### 1. 절차의 범위 정하기

사람이 해야 하는 모든 수동 단계와 그 과정에서 받는 모든 값을 파악한다. 무작정 묻지 말고 먼저 저장소를 읽는다.

- 설정의 경우: `.env`, `.env.example`, `.env.*`, `README`, `docker-compose*`, 프레임워크 설정, `.github/workflows/*` (모든 `secrets.*` / `vars.*` 참조는 마법사가 만들어야 하는 값이다).
- 마이그레이션이나 전환의 경우: 현재 상태, 목표 상태, 그 사이의 되돌릴 수 없는 작업.

그런 다음 순서대로 정리한 단계 목록과 각 단계가 만드는 값을 사용자에게 보여주고 확인받는다. 사용자는 단계를 추가하거나, 빼거나, 순서를 바꿀 수 있다.

**완료 조건:** 모든 단계에 순서대로 이름이 붙어 있고, 받는 각 값에 대해 (a) 사람이 어디서 얻는지, (b) 어디에 기록되는지(`.env`, GitHub 시크릿, 둘 다, 또는 기록 안 함. 어떤 단계는 순수한 작업이다), (c) 시크릿(숨김 입력)인지 공개 값인지를 알고 있다.

### 2. 각 단계의 경로 그리기

각 단계마다 사람이 따라갈 정확한 경로를 적는다. 어떤 URL을 열고, 거기서 무엇을 하고, 값이 어디에 표시되고, 그 값이 어떤 변수를 채우는지. 예: "Dashboard → Developers → API keys → Reveal test key → copy". 현재 UI나 정확한 명령을 실제로 모른다면 그렇다고 말하고 사용자에게 묻거나 문서를 확인한다. 존재하지 않을 수도 있는 단계를 절대 지어내지 않는다.

**완료 조건:** 모든 단계가 처음 보는 사람도 따라 할 수 있는 구체적인 지시로 이어진다.

### 3. 마법사 작성하기

`template.sh`를 대상 경로로 복사한다. 예시 단계를 단계별 `stage` 하나씩으로 의존성 순서대로 교체한다. 라이브러리 헬퍼를 사용한다: `stage`, `say`/`step`, `open_url`, `ask`/`ask_secret`, `write_env`, `set_secret`/`set_var`, `pause`/`confirm`. `TOTAL_STAGES`를 작성한 단계 수로 설정한다.

템플릿이 정한 기준을 지킨다. 값을 묻기 전에 URL을 먼저 열고, 시크릿은 모두 `ask_secret`을 쓰고, 저장되는 모든 값은 `write_env`하고, CI에 실제로 필요한 값만 `set_secret`하고, 되돌릴 수 없는 작업 전에는 `confirm`한다. 각 `stage`는 화면을 지워 현재 단계만 보이게 하므로, 한 단계는 하나의 집중된 작업으로 유지해 사람이 봐야 할 내용이 스크롤로 밀려나지 않게 한다. 마커 위의 라이브러리는 건드리지 않는다.

### 4. 검증하고 넘겨주기

- `bash -n <script>`; 가능하면 `shellcheck`를 실행한다.
- `chmod +x <script>`.
- 직접 처음부터 끝까지 실행하지 않는다. 브라우저를 열고 사람의 입력을 기다리며 멈추기 때문이다. 대신 정적으로 추적한다. 1단계의 모든 값이 받아지고 1단계에서 정한 곳에 기록되는지, 모든 `set_secret` 이름이 CI의 `secrets.*` 참조와 정확히 일치하는지 확인한다.
- 사용자에게 실행 방법을 알려준다. 반복 가능한 설정 경로라면 커밋하고 README에서 링크해, 다음 사람이 AI에게 묻는 대신 스크립트를 실행하게 한다.
